# Contributor recognition

The project recognizes more than code. Useful contributions include implementation, tests, reviews, documentation, public methodology, reproducibility work, issue triage, community support, and authorized compatibility fixtures.

## Recognition policy

- Merged contributions remain visible in Git history and GitHub's contributor graph.
- Release notes should credit material code, documentation, methodology, and fixture contributions by GitHub handle unless the contributor requests otherwise.
- Fixture provenance sidecars should record the contributor or institution only when attribution is authorized and desired.
- Reviewers may be credited when their technical review materially changes safety, privacy, compatibility, or scientific quality.
- Synthetic reproductions and negative results are recognized when they prevent unsupported claims or regressions.
- Employers or sponsors may be acknowledged only with permission; acknowledgement never implies project control or endorsement.

Recognition does not depend on contribution size. Maintainers should make a reasonable effort to correct missing or unwanted attribution in the next release notes.

## Becoming a maintainer

Maintainer access is earned through sustained, public, constructive work across implementation or documentation and review. Candidates should demonstrate respect for privacy boundaries, evidence-based compatibility claims, Apache-2.0/DCO compliance, and the project's independent community scope.

Repository permissions must not be exchanged for funding, data access, or commercial influence.
